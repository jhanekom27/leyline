leyline guide

leyline guide

Private, peer-to-peer chat for the terminal. leyline has no accounts, central message server, or shared public channel directory. A channel invite is the capability that lets another person join.

Start here

  1. Install a recent stable Rust toolchain, then run cargo run.
  2. In one instance, run /invite to show a channel ticket.
  3. In another instance, paste that ticket with /join <ticket>.
  4. Chat normally, or continue to Folder sync to share a channel’s working folder safely.

Tip: Two local test instances need separate homes. Run one with HOME=/tmp/leyline-a cargo run and the other with HOME=/tmp/leyline-b cargo run. Set CARGO_HOME to your normal Cargo home if you do not want each temporary home to rebuild dependencies.

What the badges mean

The channel list separates ordinary group channels from one-to-one conversations:

  • # is an invited group channel.
  • @ is a private message channel.
  • ⚡ is a direct point-to-point conversation.

All three channel kinds can use folder sync. A group channel needs an invite ticket before someone else can join it; a /msg or /dm conversation already has its one peer, so each person only needs to enable sync in that conversation.

Find your way around

  • /help lists commands and keybindings in the terminal.
  • /folder shows where a channel’s local files live. /folder <path> changes the shared files root for every channel on this device.
  • /files shows files shared in the active conversation and lets you save them manually.
  • /sync reports the active channel’s sync policy, status, and any current conflicts.

This guide grows with leyline. Use the GitHub link in the header to report a problem or suggest an improvement.

Install leyline

Use a published binary if you want to chat with leyline. Building from a checkout is for contributors and people who deliberately want to build from source.

Download a release binary

Open the project’s GitHub Releases page and download the archive for your platform:

  • Apple Silicon macOS: leyline-aarch64-apple-darwin.tar.xz
  • Intel macOS: leyline-x86_64-apple-darwin.tar.xz
  • x86_64 Linux: leyline-x86_64-unknown-linux-gnu.tar.xz
  • x86_64 Windows: leyline-x86_64-pc-windows-msvc.zip

Every archive has a matching .sha256 file. Download both, then verify the archive before extracting it:

shasum -a 256 -c leyline-aarch64-apple-darwin.tar.xz.sha256

On macOS or Linux, extract the archive and move leyline to a directory on your PATH:

tar -xf leyline-aarch64-apple-darwin.tar.xz
install -m 755 leyline-aarch64-apple-darwin/leyline ~/.local/bin/leyline

On Windows, use Explorer’s Extract All action for the ZIP archive, then move leyline.exe to a directory on your PATH. PowerShell can verify the published checksum with:

(Get-FileHash leyline-x86_64-pc-windows-msvc.zip -Algorithm SHA256).Hash

Compare that value to the hash in the matching .sha256 file.

Run leyline --version to confirm that the installed executable is available.

Install from source with Cargo

If you already use Rust, Cargo can build leyline from a specific published release tag:

cargo install --git https://github.com/jhanekom27/leyline --tag v<VERSION> leyline

Replace <VERSION> with a release version such as 0.18.0. This path needs a supported Rust toolchain and compilation tools; use a prebuilt archive when you only want to run leyline.

Contribute to leyline

For development, clone the repository and build from the checkout:

git clone https://github.com/jhanekom27/leyline.git
cd leyline
cargo run

Contributors use the repository’s Rust and Taskfile commands to build, test, and maintain the project. That tooling is not needed to install a published binary.

60-second quickstart

Run two leyline peers, share a private channel invite, and send a message. For two real people, each person runs the same commands in their own clone. For a local test, use two terminals and the separate HOME directories below.

1. Build leyline

git clone https://github.com/jhanekom27/leyline.git
cd leyline
cargo build

2. Start Alice

In the first terminal, run:

HOME=/tmp/leyline-alice target/debug/leyline

At the prompt, create a channel just for this demo:

/join demo

Then create an invite ticket:

/invite

Copy the ticket leyline prints. It is the private capability to join this channel, so send it only to the person you mean to invite.

3. Start Bob

In a second terminal, run:

HOME=/tmp/leyline-bob target/debug/leyline

Paste Alice’s ticket into Bob’s message box:

/join <Alice's ticket>

Both peers now have #demo open. Type a message in either pane and press Enter; it appears for the other peer shortly afterward.

Next steps

  • Use /invite whenever you want to add another person to a group channel.
  • Use /msg for an invite-backed one-to-one conversation, or /dm to message a known endpoint directly.
  • Read Folder sync to safely share a channel folder.

#general is private too: each fresh installation starts with its own secret, so create a named channel such as #demo before sharing an invite with a second fresh instance.

Folder sync

Folder sync keeps the regular files in a channel’s local folder aligned between its members. It is designed for a small shared working set, not as an unattended backup service.

Supported today: group channels (#), private-message channels (@), and point-to-point conversations (⚡). Every participant enables sync on their own local copy of the conversation.

Set up two instances

Use two devices, or two local instances with distinct HOME directories. Each instance needs leyline running.

  1. Choose the channel to share.

    • For a group channel, run /invite on the first instance, send the ticket through a trusted channel, then paste it on the second instance with /join <ticket>.
    • For a /msg or /dm conversation, start or open that conversation on both instances first. No separate folder-sync invite is needed.

  2. On each instance, select the same channel and run:

    /sync publish-and-receive

    This publishes eligible local changes and receives eligible changes from peers. /sync on is an alias for the same policy.

  3. Run /folder on either instance to see that channel’s local folder. The default root is Downloads/leyline; each channel gets its own safe folder. Change the root for this device with /folder <path> if needed.

  4. Add or edit a small file in one channel folder. leyline waits until a file is unchanged for two scans before publishing it, then the other instance downloads it into its matching channel folder.

If one participant should only download shared files, use /sync receive-only there instead. /sync off disables both directions for the active channel.

Read the status

The active channel’s /sync output reports its policy, folder, rules, pending transfers, conflicts, errors, and last successful sync. Its sidebar badge gives a compact signal:

BadgeMeaningWhat to do
SSync is idle and healthy.Continue working.
~One or more changes are pending.Wait for the file to stop changing and for a peer to be reachable.
CA conflict needs your decision.Run /conflicts.
!A sync operation failed.Run /sync and /activity for the affected path.
PSync is paused.Run /sync resume when ready.

Pause without losing your selected direction:

/sync pause
/sync resume

Resuming restores the previous receive-only or publish-and-receive policy; it does not silently switch a download-only channel into publishing.

Safety model

leyline favors preserving a copy over silently overwriting or deleting work.

Conflicts never overwrite a local file

If a remote update targets a path that already has a local file, leyline saves the remote bytes under a name such as report (remote conflict 1).txt and marks the channel C. Inspect the choices with:

/conflicts

Resolve an individual path deliberately:

/conflicts local <path>
/conflicts remote <path>
/conflicts both <path>

Keeping local or remote moves the displaced copy into recoverable sync trash. Keeping both leaves both copies in place. No conflict command silently overwrites a file.

Remote deletes are recoverable

When a remote delete applies to an unchanged file that sync previously wrote, leyline moves it into that channel’s hidden .leyline-trash folder rather than deleting it permanently. A local edit turns a remote delete into a conflict instead.

Use these commands to inspect and control recovery:

/trash
/trash restore <path>
/trash purge

Trash is retained until you explicitly purge it. Restoring a path never overwrites an existing local file; leyline gives the restored copy a distinct name instead.

Scope and size are bounded

Sync recursively considers regular files in the channel folder, but does not publish:

  • hidden paths, including .leyline-trash;
  • the local-only send/ outbox;
  • symbolic links;
  • common editor and download temporary files such as *.part, *.tmp, *.swp, *.crdownload, and names starting with ~$.

Incoming sync files over 500 MB are skipped. This is a fixed sync safety limit, independent of /maxsize, which controls the files you share manually.

You can further scope a channel with relative glob rules:

/sync include docs/**
/sync exclude docs/private/**
/sync remove include docs/**
/sync clear-rules

When include rules exist, only paths matching an include rule are eligible. Excludes always win. Rules use / separators and cannot point outside the channel folder.

Troubleshoot deliberately

  1. Confirm both people are in the same conversation: the same invited group channel, or the same /msg or /dm pair.
  2. Run /sync on both instances and check for P, C, or !.
  3. Run /activity to see the latest local outcome for each affected path.
  4. Ensure the file is not hidden, temporary, oversized, or beneath send/.
  5. If files disagree, inspect /conflicts before modifying either copy.
